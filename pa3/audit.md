# PA3 Audit

## Audit Plan

- Inspect assignment and test contracts: `TESTING_AND_REFERENCES.md`,
  `pa3/README.md`, `pa3/plan.md`, `pa3/tests/`, and
  `cppgm.tests/course/pa3/`.
- Inspect the PA3 implementation files from the current stage commit:
  `dev/ctrlexpr.cpp`, `dev/src/ctrlexpr_support.h`,
  `dev/src/ctrlexpr_support.cpp`, and `dev/frontend_source_sets.mk`.
- Check earlier-stage ownership boundaries: PA1 phase 1-3 behavior remains in
  `dev/src/pptoken_lib.cpp`, PA2 token/literal facts remain in
  `dev/src/posttoken_support.cpp`, and PA3 does not recover semantics from
  formatted debug output.
- Audit for skipped compiler phases, fallback success paths, dummy output,
  shell-outs, embedded reference/runtime payloads, source-shape gates, or
  test-specific branches in the PA3 path.
- Audit expression semantics around token conversion, integral literal typing,
  character literal signedness, `defined`, alternative operator spellings,
  arithmetic conversions, short-circuit parsing/evaluation, division/modulo by
  zero, shift limits, conditional result typing, and line splitting.
- Audit performance risks: repeated full-line scans, avoidable quadratic parser
  behavior, excessive token copying, recomputation in hot expression paths, and
  any timeout-oriented workaround.
- Audit file-integrity risks: new source registration in
  `dev/frontend_source_sets.mk`, file-audit coverage of `dev/src`, hidden
  implementation fragments outside checked source paths, oversized files, or
  weakened audit checks.

## Findings

- Found duplicated ownership of PA2 literal facts: `dev/posttoken.cpp` and
  `dev/src/ctrlexpr_support.cpp` each carried their own integer literal
  suffix/type selection and character literal decoding helpers.  The behavior
  matched current tests, but it left PA2 and PA3 with parallel semantic owners
  for facts that should be represented once.
- Confirmed `ctrlexpr` executes PA1 phases 1-3 through
  `pptoken::run_pptoken`, splits logical lines on preprocessing new-line
  events, ignores whitespace-only lines, and returns `EXIT_FAILURE` only for
  phase/tokenization exceptions from the shared PA1 path.
- Confirmed PA3 output is generated by the parser/evaluator, not by dummy
  lines, shell-outs, reference binaries, template binaries, embedded payloads,
  trampolines, interpreters, VMs, or source/test-name gates.
- Confirmed the parser rejects invalid tokens and malformed grammar, parses
  skipped `&&`, `||`, and `?:` branches for validity, suppresses only
  runtime-only inactive-branch errors, preserves conditional result unsignedness
  from both branches, and rejects active division/modulo by zero and invalid
  shift counts.
- Confirmed no timeout workaround, repeated full-suite walk inside the tool,
  avoidable quadratic line scan, hidden unchecked source path, or weakened
  file-audit check was present.

## Changes Made

- Moved shared integer and character literal analysis into
  `dev/src/posttoken_support.{h,cpp}`:
  - integer suffix parsing, base/value range checks, candidate type selection,
    user-defined integer suffix detection, and signedness classification;
  - character literal prefix/body parsing, UTF-8 and escape decoding,
    code-point validation, user-defined suffix checks, and byte append helpers.
- Updated `dev/posttoken.cpp` to call the shared literal analysis while keeping
  PA2-specific floating literal handling, string concatenation, and debug output
  formatting local to the `posttoken` tool.
- Updated `dev/src/ctrlexpr_support.cpp` to convert shared typed integer and
  character literal facts into PA3 `intmax_t`/`uintmax_t` expression values and
  reject user-defined/non-integral literals directly.
- Updated `pa3/plan.md` with `Architecture Review` and
  `Final Architecture Review` sections grounded in the final source layout.
