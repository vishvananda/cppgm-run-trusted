# PA4 Audit

## Audit Plan

- Source files: inspect `dev/macro.cpp`, `dev/posttoken.cpp`,
  `dev/src/pp_token.{h,cpp}`, `dev/src/posttoken_pipeline.{h,cpp}`,
  `dev/src/macro_support.{h,cpp}`, and `dev/frontend_source_sets.mk`
  against the PA4 README and existing PA1/PA2/PA3 behavior.
- Tests and references: review the PA4 handout tests, course PA4 tests, and
  earlier through-PA tests for regressions in tokenization, posttoken output,
  directive parsing, macro redefinition, recursion, stringization, token
  pasting, variadics, and error handling.
- Compiler-integrity risks: search for skipped phases, dummy output paths,
  fallbacks to reference binaries or host compilers, embedded payloads,
  interpreter/VM/trampoline/template-binary substitutes, and source-shape or
  fixture-specific acceptance gates.
- Ownership boundaries: verify that preprocessing-token capture belongs to
  `pp_token`, PA2 token emission belongs to `posttoken_pipeline`, macro
  semantics and blue-paint state belong to `macro_support`, and CLI wrappers
  only orchestrate those modules.
- Semantic representation risks: check for stringly macro facts,
  downstream recovery of macro kind/parameters/replacement state, duplicated
  ownership of unavailable-name paint, and places where whitespace/newline
  meaning is reconstructed after being discarded.
- Performance risks: inspect rescanning, argument expansion, token pasting,
  replacement comparison, and output conversion for avoidable quadratic scans,
  repeated full-suite walks, excessive token copying, timeout workarounds, or
  hot-path recomputation.
- File-audit issues: run the stage file audit and inspect source size,
  generated-code hiding, unchecked implementation fragments, weakened checks,
  and code moved outside `dev/src` or omitted from `dev/frontend_source_sets.mk`.

## Findings

- Found a PA4 blue-paint blocker in `dev/src/macro_support.cpp`: function-like
  replacement tokens and tokens created by `##` could lose unavailable-name
  state from the macro head.  This allowed nested object-like macro names to be
  reconstructed and expanded again instead of remaining painted.  Audit probes
  such as `#define F(x) G ## x` with `#define G0 F(0)` timed out before the
  fix, while the reference emitted `identifier G0`.
- Confirmed the fix had to preserve PA4's helper-rescan behavior.  Marking
  every function-like replacement token with all head unavailable names broke
  the existing `600-parameter-selected-macro-rescans` and
  `600-tail-helper-macro-rescans` course tests, so the final logic marks
  object-like unavailable names immediately and function-like unavailable
  names only when the call is present in the replacement context.
- No skipped compiler phases, dummy outputs, reference-binary fallbacks,
  host-compiler fallbacks, embedded payloads, interpreter/VM/trampoline
  substitutes, fixture-specific gates, timeout workarounds, file-audit
  bypasses, or hidden implementation fragments were found in the PA4-owned
  source files.
- No ownership blocker was found after the fix: token capture remains in
  `pp_token`, PA2 output conversion remains in `posttoken_pipeline`, PA4 macro
  state remains in `macro_support`, and CLI files remain orchestration only.
- No remaining performance blocker was found.  Rescanning is local to text
  sequences and replacement lists; the nontermination risk from lost paint was
  fixed as semantic state propagation rather than by adding a timeout.

## Changes Made

- Updated `process_pastes` to carry unavailable-name paint from both paste
  operands onto retokenized `##` results.
- Passed macro-head context into paste processing so a pasted identifier that
  reconstructs an unavailable object-like macro name remains unavailable.
- Refined replacement-token painting so function-like helper macros are not
  incorrectly disabled when their call is formed later by rescan, preserving
  existing helper-tail behavior.
- Added `cppgm.tests/course/pa4/610-unavailable-paint-through-function-replacement.t`
  with reference output generated by the PA4 `macro-ref` runner from the
  `pa4/` harness directory.

## Validation

- Targeted audit probes for nested function-like replacement and `##`
  reconstruction now terminate and emit `identifier G0`.
- `make -C pa4 test` passed with 38/38 handout tests and 31/31 course PA4

- `perl scripts/cppgm_file_audit.pl --stage pa4 --paths dev/src` passed.
- `make test-pa4` passed with 38/38 handout tests and 31/31 course PA4 tests.
- `make test-report-through-pa4` passed with 156/156 tests through PA4.
- Final `perl scripts/cppgm_file_audit.pl --stage pa4 --paths dev/src`
